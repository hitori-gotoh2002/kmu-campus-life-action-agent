처음 보는 사용자가 설정, 추천 확인, 텔레그램 승인, Notion 추가, 졸업 진단까지 이해하도록 만든 운영 흐름 문서입니다.

Streamlit 웹 Supabase 원격 DB GitHub Actions 08시 자동화 Telegram 승인 Notion 캘린더 수강내역 엑셀 졸업진단

1. 한눈에 보는 서비스 구조

사용자가 보는 곳

웹: 설정, 추천함, 졸업 진단을 사용합니다.

텔레그램: 추천을 받고 버튼으로 승인합니다.

Notion: 승인된 일정과 실제 개인 일정을 봅니다.

데이터가 저장되는 곳

Supabase: 추천, 설정, 프로필, 시간표, 졸업 데이터를 저장합니다.

Notion: 실제 일정 캘린더와 포트폴리오만 저장합니다.

자동으로 도는 곳

GitHub Actions: PC가 꺼져 있어도 매일 08시에 추천을 업데이트합니다.

Callback Processor: 5분마다 텔레그램 버튼을 확인합니다.

2. 첫 사용 흐름

1 웹 실행

터미널에서 streamlit run app.py 실행 후 localhost:8501 접속

2 키 입력

설정 화면에서 OpenAI, Notion, Telegram 정보를 저장

3 시간표 저장

시간표 PDF를 업로드하거나 표를 직접 입력해 수업 시간을 분리

4 추천 새로고침

분야별 공지를 수집하고 내 상황에 맞는 후보를 추천함에 저장

5 선택 실행

필요한 추천은 Notion에 추가하고, 필요 없는 추천은 무시

3. 웹 화면별 역할

홈
  • 현재 프로필 요약을 보여줍니다.
  • 내 맞춤 추천함과 졸업 진단으로 이동합니다.
  • 하단에서 현재 저장소가 Supabase인지 확인할 수 있습니다.
설정
  • API 키와 DB ID를 입력합니다.
  • 시간표 PDF를 업로드하고 추출 결과를 수정합니다.
  • 분야별 자동수신 주기와 채널을 정합니다.
내 맞춤 추천함
  • 분야 박스를 눌러 누적 추천을 확인합니다.
  • 추천된 날짜, 요약, 이유, 마감일, 원문 링크를 봅니다.
  • 노션에 추가하거나 무시합니다.
졸업 진단
  • ON국민 수강내역 엑셀을 업로드합니다.
  • 과목 포함 여부와 이수구분을 검토하고 수정합니다.
  • 이수 완료 과목과 부족 학점이 추천 기준에 반영됩니다.

4. 추천이 만들어지는 과정

단계 무엇을 하나요? 관련 파일
수집 국민대 공지, 장학공지, 링커리어 공모전/대외활동/채용/자격증 정보를 가져옵니다. modules/scraper.py
분류 장학금, 공모전·대회, 대외활동·서포터즈, 학사일정, 채용·인턴, 자격증, 기타로 나눕니다. modules/classifier.py
분석 LLM이 내용을 읽고 요약, 추천 이유, 예상 시간, 적합도 점수를 만듭니다. modules/analyzer.py
검증 시간표, Notion 실제 일정, 시험기간을 반영해 무리한 추천을 보류합니다. modules/validator.py
저장 추천완료, 승인, 거절, 보류/제외 상태를 Supabase에 저장합니다. modules/store.py
실행 사용자가 승인하면 Notion 캘린더에 준비 일정과 상세 설명을 추가합니다. modules/executor.py

5. 자동화 타임라인

매일 08:00
GitHub Actions가 추천 파이프라인을 실행합니다. PC가 꺼져 있어도 동작합니다.
분석 직후
추천 결과가 Supabase 원격 DB에 저장됩니다. 텔레그램 수신 분야는 메시지로 발송됩니다.
버튼 클릭
사용자가 텔레그램에서 노션 추가 또는 무시를 선택합니다.
최대 5분 내
Callback Processor가 버튼을 확인하고, 승인된 추천을 Notion 캘린더에 등록합니다.
PC 켠 뒤
로컬 웹을 열면 Supabase에 저장된 최신 추천을 읽어옵니다.

6. 추천 카드에서 봐야 할 것

참여 여부 판단 기준

  • 내 전공/희망직무와 관련 있는가?
  • 마감일까지 준비할 시간이 충분한가?
  • 시험기간이나 바쁜 일정과 겹치지 않는가?
  • 포트폴리오에 실제로 도움이 되는 산출물이 남는가?

상태의 의미

  • 추천완료: 추천함에 표시되는 후보
  • 승인: Notion에 추가한 후보
  • 거절: 사용자가 무시한 후보
  • 보류/제외: 시간, 마감, 관련도 조건에서 제외된 후보
새로고침은 기존 추천을 지우지 않습니다. 새 후보를 추가하거나 같은 URL의 정보를 갱신합니다. 설정에서 끄기로 둔 분야는 자동 실행과 수동 새로고침 모두에서 제외됩니다.

7. 처음 운영할 때 체크리스트

확인 해야 할 일 정상 기준

Notion 캘린더 DB와 포트폴리오 페이지에 통합 연결 노션에 추가 버튼이 일정 생성
웹 streamlit run app.py 실행 localhost:8501 접속 가능

8. 장애가 생겼을 때 빠른 판단

증상 가장 먼저 볼 곳
추천이 안 쌓임 GitHub Actions Daily KMU Digest 로그, 웹 설정의 분야별 주기, DIGEST_CATEGORIES override 여부
텔레그램이 안 옴 웹 설정의 텔레그램 채널, TELEGRAM_CATEGORIES override 여부, Telegram Secrets, Actions 실행 결과
승인했는데 Notion에 안 들어감 Telegram Callback Processor 로그, Notion 캘린더 DB 연결
웹에는 예전 데이터만 보임 STORE_BACKEND, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, 웹 재시작 여부
추천이 너무 적음 시험기간 가용시간, SOURCE_FOCUS_FILTER, 끄기 설정, 마감 지난 공고 여부
기준 파일: app.py, pages/0_설정.py, pages/1_내_맞춤_추천함.py, pages/2_졸업_진단.py, modules/store.py, modules/digest.py, modules/telegram_callbacks.py, .github/workflows.
